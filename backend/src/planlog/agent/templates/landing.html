The problem

Same agent. Different session.

Every fresh context window starts from zero. What it starts from is the whole game.

Without a plan

  • You re-explain the goal from scratch.
  • The agent re-derives scope and guesses at the edges.
  • It ships something adjacent to what you meant.
  • The decision lives in a chat log nobody can find.

With Planlog

  • get_plan(plan_id) — intent, scope, acceptance criteria.
  • The agent codes against criteria a human already approved.
  • post_done records what actually shipped, with links.
  • The next session starts where the last one ended.

How it works

Pull requests, but for the plan.

Draft → review → approved → Done. If you've shipped a PR, you already know this loop.

  1. 1

    Plan

    Intent, scope, acceptance criteria. Markdown, not a ticket form.

  2. 2

    Approve

    Reviewers approve or request changes — before a line of code exists. Agents edit while the plan is a draft or has changes requested.

  3. 3

    Done

    On ship, the agent calls post_done with a summary and links. That record is permanent.

Install

One command. Every agent on your machine.

No Planlog clone. The installer asks where to install and which agents to wire up, then writes the right config file for each one.

Use

From plan_id to shipped.

  1. Sign up, create an organization, and write a markdown plan.
  2. Run the install in your repo, then paste the plan_id into your agent.
  3. The agent runs get_plan → writes code → post_done with a summary and links.
  4. Teammates approve, suggest changes, or get notified on Done.

Why it sticks

Your agent forgets. The plan doesn't.

  • Done is history

    A permanent record of what shipped — not a Slack thread that ages out.
